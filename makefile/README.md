# Makefile for a project

You are given a small C project with **no Makefile**. Your job is to write one.

project layout:
```
project/
├── include/         <- public headers
│   ├── add.h
│   ├── sub.h
│   ├── mul.h        <- generated later
│   └── stats.h
├── src/             <- sources
│   ├── main.c
│   ├── add.c
│   ├── sub.c
│   ├── mul.c        <- generated later
│   └── util/        <- more sources
│       └── stats.c
├── tests/           <- tests
│   └── test.sh
├── tools/           <- a generator that writes src/mul.c and include/mul.h
│   └── genmul.c
└── Makefile          <- write it
```

For compilation use `gcc` with flags `-Wall -Wextra -O2 -Iinclude`

## Task 1
Produce a working `Makefile` that builds and runs the program.
! For the current task ignore `project/tools/genmul.c` !

### Requirements
- Default target `all` builds the binary `prog` at `build/project` from **all** `.c`
  files under `src/` (including `src/util/`).
- Object files go under `build/`, **mirroring source paths**:
  `src/util/stats.c` -> `build/util/stats.o`.
- The include directory is passed to the compiler so `#include "add.h"` etc.
  resolve.
- `clean` removes `build/`.

### Acceptance
    make clean && make
    ./build/prog
    # prints:
    #   add: 5
    #   sub: 6
    #   mul: 42
    #   sum: 15
    make clean

---
## Task 2
Make the build correct under change, without hardcoding filenames.
! For the current task ignore `project/tools/genmul.c` !

### Requirements
- **No hardcoded source list.** Discover `.c` files under `src/`
  automatically.
- **Header tracking.** Editing any file under `include/` must rebuild
  only the affected objects on the next `make`. Hint: `-MMD -MP` plus
  `-include $(DEPS)`.
- **Incremental.** A second `make` with no changes prints
  `make: Nothing to be done for 'all'.` (or equivalent) and runs no `gcc`.
- **Parallel-safe.** `make -j4` from a clean tree must succeed with no
  race conditions. Hint: `mkdir -p` plus order-only prerequisites (`|`)
  for directory creation.
- **Phony targets.** `all`, `clean`, and `test` must be `.PHONY`.

### Acceptance
    make clean && make          # builds everything
    make                        # no gcc lines
    touch include/add.h
    make                        # rebuilds add.o, main.o, relinks only
    make -j4 clean all          # succeeds

---
## Task 3

Integrate the `genmul` tool into the build so `src/mul.c` and
`include/mul.h` are produced on demand.

### Requirements (adds to Subtask 2)
- `tools/genmul.c` is compiled into `build/genmul` before any source
  that needs it.
- `src/mul.c` and `include/mul.h` are generated by running `build/genmul`
  when they are missing or older than `tools/genmul.c`.
- **No rebuild loop.** After a successful build, a second `make` must be
  a no-op. The generator must not run on every invocation.
- `make test` builds the program and runs `tests/test.sh`.
- `make clean` must leave the tree in a state where a subsequent
  `make` regenerates and rebuilds everything correctly.

### Acceptance
    make clean && rm -f src/mul.c include/mul.h
    make                        # builds genmul, runs it, builds calc
    ./build/calc                # prints mul: 42
    make                        # no-op (make: Nothing to be done)
    touch tools/genmul.c
    make                        # regenerates mul.c and mul.h, rebuilds
    make -j4 clean all          # succeeds
    make test                   # prints PASS

### Hint 1 -- Build the generator like any other program
The generator is just a C program. Give it its own rule, exactly like you would for `build/prog`:
```
build/genmul: tools/genmul.c
	$(CC) $(CFLAGS) $< -o $@
```

### Hint 2 -- Depend on the generator binary, not on tools/genmul.c
When you write the rule that runs the generator, the prerequisite must be `build/genmul` (the compiled binary), not `tools/genmul.c` (the source of the generator).

Wrong:
```
src/mul.c: tools/genmul.c
	./build/genmul
```
Correct:
```
src/mul.c include/mul.h: build/genmul
	./build/genmul
```
Rule: depend on the thing that produces your output, not on the thing that produces the producer.

### Hint 3 -- One invocation, two outputs
`tools/genmul` writes both src/mul.c and include/mul.h in one run. Your Makefile must reflect that, or you'll hit two problems.

Wrong:
```
src/mul.c: build/genmul
	./build/genmul

include/mul.h: build/genmul
	./build/genmul
```
Correct:
```
src/mul.c include/mul.h &: build/genmul
	./build/genmul
```

### Hint 4 — Make build/mul.o wait for both generated files
Your generic pattern rule `(build/%.o: src/%.c)` knows that `build/mul.o` comes from `src/mul.c`. It does not know that `build/mul.o` also depends on `include/mul.h`.
Add an explicit dependency line:
```
build/mul.o: src/mul.c include/mul.h
```

# Checklist
**task 1**
- make clean && make produces build/calc
- ./build/calc prints the four expected lines
- make clean removes build/

**task 2**
- No hardcoded source list in the Makefile
- touch include/add.h && make rebuilds add.o and main.o, relinks
- Second make is a no-op
- make -j4 clean all succeeds
- all, clean, test declared .PHONY

**task 3**
- make clean && rm -f src/mul.c include/mul.h && make succeeds end-to-end
- Second make after that is a no-op (no rebuild loop)
- touch tools/genmul.c && make regenerates and rebuilds
- make -j4 clean all succeeds
- make test prints PASS
